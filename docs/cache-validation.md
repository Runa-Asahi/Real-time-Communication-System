## 已实现内容

- `LruCacheFanLX` 使用两条 `std::list` 与一个 `std::unordered_map`，Entry 包含 `freq` 和 `CacheLevel`；Buffer/Main 各自按条数与字节预算裁剪，主区淘汰不降级。
- `ArcCacheFanLX` 使用 L1/L2/B1/B2 四区与单路由表；L1 记录最近 K 次访问，B1/B2 命中调节 `p`，L2 由 LFU 频次和 LRU 位置共同决定淘汰。
- `LfuFrequencyFanLX` 独立维护总频次、平均上限、周期老化、计数饱和与衰减次数。
- `MemoryPoolFanLX` 支持过对齐对象、BlockSize=1、构造失败归还槽位、未归还对象析构和禁止浅复制。
- `QueryCacheFanLX` 以 JSON 结构化键保存好友、共同好友、跨服务推荐和群成员结果，键中包含局部版本；权限校验在缓存访问前完成。缓存异常只回源，不改变业务结果。
- `ConsoleAppFanLX` 提供数字菜单、严格 `from_chars` 数字解析、返回/EOF、恢复确认、服务登录、好友群操作和保存退出。

## T13 测试与基准

`query_cache_tests` 固定种子 2026，覆盖 2Q 两区约束、LFU 平均限制/溢出/周期老化、ARC 高频淘汰、幽灵历史回源、随机 20000 步容量不变量、内存池过对齐和构造失败、缓存命中/失效/越权/开关一致性。`console_tests` 使用注入流覆盖非法数字、中文备注、菜单返回、EOF、保存退出和未登录权限。

默认 CTest 6/6，Release CTest 6/6；默认总耗时 6.19 s，Release 总耗时 3.92 s。CMake 对 MinGW 使用 `-static`，避免 PATH 中旧 `libstdc++` 抢先加载。

`cache_benchmark` 通过真实应用查询入口，固定种子 2026，构造 1012 用户、112 群，执行 hot/mixed/scan 三种工作负载，每种 1000 次查询 × 5 轮 × 缓存开关两种模式；每次比较返回值并记录 p50/p95、命中/未命中、逻辑载荷字节、池保留字节和写事务耗时。结果位于 `.artifacts/S07/cache-benchmark.csv`。
